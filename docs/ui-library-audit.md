# UI library audit: sonner, vaul, @number-flow/react, cmdk

Read-only audit of `src/app/**` and `src/components/**` on branch `chore/add-ui-libraries` (Next 16.4.6, React 19.3).
Installed versions: sonner 2.0.8, vaul 1.1.2, cmdk 1.1.1, @number-flow/react 0.6.2. All four list React 19 as a peer dependency.

## Ground rules found during the audit

- **Server/client boundary.** sonner, vaul and cmdk ship `'use client'` at the top of their `dist/index.mjs`. Per `node_modules/next/dist/docs/01-app/01-getting-started/05-server-and-client-components.md` ("Third-party components"), that means they can be imported straight into a Server Component. So `<Toaster />` can go in the server `src/app/layout.tsx` with no wrapper. @number-flow/react has no top-level directive (its client code lives in a `NumberFlow-client-*.mjs` chunk). That doesn't matter here, because every file that would render it (`ui.tsx`, the pages, `ProgressView`, `TrainingCalendar`) is already `"use client"`.
- **Dark mode.** The app themes itself with `@media (prefers-color-scheme: dark)` in `globals.css`, and there is no theme provider. Sonner's default theme is `'light'`, so the Toaster needs `theme="system"`.
- **Fixed chrome on mobile.** A bottom nav (`AppShell.tsx:186`, z-30, ~4rem plus the safe-area inset) and the rest timer (`session/[id]/page.tsx:403`, bottom 4.75rem) both sit at the bottom of the screen. Put toasts at **top-center** so they never collide with either.
- **Radix is already in `node_modules`.** It arrives transitively: vaul and cmdk are both built on `@radix-ui/react-dialog`. Adding `@radix-ui/react-dialog` as a direct dependency costs nothing extra. Radix AlertDialog, Tabs and ToggleGroup are *not* present.

## Where NOT to use them

- **No drawer per set, and no toast per set.** The inline set grid in `session/[id]/page.tsx` (`SetRow`, `:316-366`) is the fastest possible logging flow. A drawer adds taps. The offline queue already handles saves, with inline per-row state and Retry. A toast per ✓ would spam the screen mid-workout.
- **No toasts for autosave success.** Plan builder fields, exercise notes and workout notes save on blur, dozens of times per session. Keep the quiet inline status (`plans/[id]/page.tsx:66`, `session/[id]/page.tsx:383`) and toast **errors only**.
- **No toasts for form validation.** Auth (`login`, `signup`), onboarding, `MealForm`, `CustomExerciseForm`, `BodyWeight`, `TargetsForm` validation stay inline in `Field`/`ErrorBox`, next to the input that needs fixing.
- **Offline banner stays a banner** (`AppShell.tsx:176-180`). It is persistent state, not an event. A toast would time out while the user is still offline.
- **"Workout saved" + PR card on Today** (`today/page.tsx:93-100`, `SessionPrs`) stays inline. It is a celebration with content (PR list), which is too much for a toast and too important to auto-dismiss.
- **Chat send failures** (`ChatThread.tsx:154`) stay inline on the bubble with Retry. The error belongs to a specific message.
- **Rest timer** is neither a toast nor a drawer. It is a non-modal, long-lived overlay with its own progress bar and should stay as built.
- **No NumberFlow on editable inputs** (weight/reps, targets, plan sets/reps), chart axes/tooltips, the Records table (`ProgressView.tsx:271`), or calendar day numbers. Those aren't values changing in response to an action.
- **Don't replace native `<select>` with cmdk** on mobile. Native pickers are the best phone UX and are accessible for free. cmdk belongs to keyboard-heavy desktop search (rows 16–17).
- **No ⌘K in the client app.** Five tabs and few destinations, used on phones.
- **No vaul `shouldScaleBackground`.** It needs a wrapper around the app and fights the fixed bottom nav and safe-area padding in a PWA.
- **Don't animate the ⌘K palette open/close** (Emil's rule: anything opened 100+ times a day gets no animation).
- **Don't adopt shadcn's Sonner/Drawer wrappers.** Write small local wrappers in `ui.tsx` style instead, keeping the decision to leave `globals.css` alone.

## Suggested implementation order

1. **Sonner foundation** (rows 1, 2, 7). Mount the Toaster, add a `notify` wrapper styled with the existing tokens (start with `toastOptions.classNames`; switch to `toast.custom` if it needs more than a few `!important`s), replace the six `alert()`s and the two invisible/inline success messages. Small and self-contained, and later rows reuse it.
2. **Undo deletes** (rows 3, 4, 9). Removes three `confirm()`s and fixes the no-safety-net exercise removal.
3. **Shared drawer** (rows 5, 6, then 15). Rebuild `Sheet` on vaul with the same props. This fixes the nested-Escape bug and the missing focus trap/scroll lock across the library, plan picker, calendar day sheet and meal form in one place. Add the Radix Dialog desktop branch right after.
4. **AlertDialog for the remaining irreversible confirms** (Radix/Base UI table). Needs a new dependency: decide Radix vs Base UI first.
5. **NumberFlow quick wins** (rows 12, 13, then 14). `Meter` alone covers Today and Nutrition.
6. **cmdk in the exercise picker** (row 16). Builds on the drawer from step 3.
7. **Coach ⌘K palette** (row 17). The largest piece; do it once the picker has proven the cmdk styling.
8. **Optional polish** (rows 8, 10, 11, 18–21, Tabs/ToggleGroup a11y).
